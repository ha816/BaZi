## 1. 목적

두 사람의 궁합을 **결과 직후 한 장**(캐릭터 칭호 + 점수)으로 각인시키고, 그다음 7개 탭을 끝까지 넘겨 보게 한다. 분석 결과 화면에 넣은 장치(인트로 → 문답 → 탭, 탭 끝 "다음 이야기", 등장 연출)를 그대로 쓴다.

지키는 원칙
- 분석 결과에 들어간 장치는 궁합에도 맞춘다 (ROADMAP V6, 2026-10-15).
- 해석 문장·점수·예측은 전부 백엔드가 만든다. 프론트는 **어디에 무엇을 어떤 순서로 보일지**만 정한다.
- 폰 한 화면 기준. 엄지로 누르는 버튼은 아래에 붙인다.
- 카드 포맷은 분석과 같다(REFACTORING §4-3). 카드 상세 설명(접힘)은 폰 기준 **4줄(390px에서 약 120자) 이내** — 더 길면 까치 팁·본문으로(2026-10-18, 사용자 지시).

## 2. 진입과 상태

- **로그인 필수.** 비로그인은 로그인 안내 카드 → `/join`, 돌아올 경로는 sessionStorage(`lib/loginNext`). 초대 링크(`?invite=`)도 같은 카드.
- 결과는 **폼을 대체**한다. 페이지 헤더 오른쪽에 [공유] [다시 입력](2026-10-23 "궁합 공유" → "공유"). 다시 입력은 결과를 지우고 주소에서 `step`·`tab`을 뺀다.
- **단계 `?step=`**
  - 새 결과(주소에 `step`·`tab`이 없음)는 `intro`부터. 주소에 `?step=intro`를 남긴다(replaceState).
  - 인트로 → 문답은 `?step=scenario`로 pushState. 폰 뒤로 가기로 인트로로 돌아온다.
  - 인트로·문답에서 "궁합 분석 보기"는 첫 탭 `?tab=character`(성격)로 pushState 하고 맨 위로 스크롤(2026-10-18, 전엔 팔자비교).
  - `?step=scenario`는 문답이 있을 때만 유효. 없으면 탭 화면.
  - `?tab=`이 있는 주소를 새로고침하면 인트로 없이 그 탭.
  - 인트로·문답이 덮는 동안 뒤 화면은 스크롤되지 않고, 탭 본문은 마운트하지 않는다(닫힌 뒤 등장 연출이 사용자 눈앞에서 돌게).
- **탭 `?tab=`** 은 replaceState로만 바꾼다(서버 왕복 없음). `invite`·`p1`·`p2`는 보존.
  - 옛 값 호환: `summary`·`total` → `character`(옛 한눈에의 캐릭터 상자가 있는 첫 탭), `element` → `pillars`, `sinsal` → `character`.
  - `?tab=daily`인데 프로필×2가 아니면 첫 탭 `character`. 문답이 없는데 `?tab=scenario`면 `character`.
- **결과당 한 번**: 시운 `GET /compatibility/forecast`(오늘부터 14일, 프로필×2일 때만, 상태에 캐시). AI 해석 스트림은 결과가 뜨자마자 페이지가 시작하고, 다시 분석하면 이전 스트림을 끊는다.
- **이벤트**: `tab_view{tab, page:"compat", has_profile}` · `share_click{channel:"compat"}` · `compat_invite_result{via:"invite"}`. 새 이벤트는 추가하지 않는다(사용자 결정 2026-09-28).

## 3. 화면 구성과 순서

### 3-1. 인트로 (`?step=intro`, 전체 화면)

1. 머리줄 "✓ 궁합 분석 완료" + 오른쪽 [건너뛰기] (펼치는 중에는 숨김)
2. **두근두근 게이트** — "두근두근 💓 / ○○님과 ○○님의 궁합은?" + 두 사람 캐릭터 실루엣(각자의 사주 캐릭터 그림을 흐리게, "?" 겹침, 가운데 ♥ — 분석 게이트와 같은 모양, 2026-10-18) + [💞 두 분의 궁합 확인하기]
3. 누르면 1.2초 드럼롤("두구두구두구…") 뒤 **캐릭터 상자**: 두 사람의 사주 캐릭터 그림 나란히 + ♥(`saju_character/{character_key}.webp`, 분석 결과와 같은 그림, 2026-10-18 — 그림이 없는 쪽만 역할 이모지) → "{관계 유형} 궁합 · 두 분은" → 칭호 → 점수 + 라벨 → 역할 칩 두 개("○○님 = 이모지 역할 (한글오행)") → 설명. 캐릭터가 없는 옛 결과는 점수 + 한 줄 설명만
4. 까치 인사 말풍선 — "○○님과 ○○님의 궁합을 풀어드릴게요." + 문답이 있으면 "아래 설문조사를 하면 사주가 두 분을 얼마나 맞히는지 알려드려요."
5. 아래 고정 버튼 — [📋 설문조사](문답 있을 때) / [💞 궁합 분석 보기]
6. 분석 보기 → "두 분의 인연 지도를 펼치는 중…" 1.3초 → 성격 탭(첫 탭 — 맨 위에 두 분의 캐릭터 카드)

### 3-2. 문답 (`?step=scenario`, 전체 화면)

1. 머리줄 "📋 설문조사" + 오른쪽 [분석 바로 보기 ›](제출 전만)
2. **설문조사 카드**(🔮, 구 "이럴 때 두 분은?") — 머리 오른쪽 "k/P 페이지 · n/N 답함", 까치 팁, 문항 블록(Q번호 + 질문 + [○○님 / ○○님 / 둘 다] 3칸), 아래 [다음 문항으로 (a~b번) ›] 또는 마지막 페이지에선 [🔮 사주 예측과 맞춰 보기], 2페이지부터 "‹ 이전 문항 (a~b번)" 링크
3. 제출 뒤 — "답변 완료!" + "사주가 두 분을 얼마나 맞혔는지는 📋 설문조사 탭에 숨겨 뒀어요. 궁합 분석을 먼저 보고 확인해 보세요." + 아래 고정 [💞 궁합 분석 보기]. **일치율은 여기서 보여주지 않는다.**

### 3-3. 탭바

고정 상단. 프로필×2면 7탭(모바일 4+3 두 줄, sm 이상 한 줄), 아니면 6탭 한 줄. 순서·라벨·"다음 이야기" 제목:

| # | `?tab=` | 라벨 | 다음 이야기 제목(hook) | 노출 조건 |
|---|---|---|---|---|
| 1 | `character` | 🎭 성격 | 두 분의 성격, 닮았을까 다를까? | 항상 |
| 2 | `pillars` | 🧩 팔자비교 | 두 분의 여덟 글자는 어떻게 맞물릴까? | 항상 |
| 3 | `daily` | 🌅 시운 | 오늘 두 분의 기운은 어떨까? | 프로필×2(memberId·profileId 둘 다) |
| 4 | `zodiac` | 🐾 띠궁합 | 띠로 보면 두 분은 어떤 사이일까? | 항상 |
| 5 | `domain` | 📊 종합점수 | 두 분의 궁합은 몇 점일까? 영역별로도 봐요 | 항상 |
| 6 | `scenario` | 📋 설문조사 | 사주가 두 분을 얼마나 맞힐까? (1분) (제출 뒤: 답해 둔 설문조사, 사주와 몇 % 맞았을까?) | `character.scenarios`가 1개 이상 |
| 7 | `ai` | ✨ AI 해석 | 까치가 두 분의 궁합을 이야기로 풀어 드려요 | 항상 |

## 4. 규칙

**한다**
- 분석 결과 화면에 들어간 장치는 궁합에도 같은 모양으로 넣는다. 둘이 다르면 분석 쪽이 기준(V6).
- 옛 캐시(JSONB)에 없을 수 있는 필드는 오케스트레이터가 한 번만 기본값으로 채운다. 영역 카드 순서는 프론트에서 고정한다(JSONB가 키 순서를 보존하지 않음).
- 캐릭터 그림은 두 사람 각자의 **사주 캐릭터**(분석 결과와 같은 파일, 규칙은 `specs/compatibility/character.md` §7·§8)를 재사용한다 — 궁합 전용 그림은 만들지 않는다(2026-10-18, 사용자 결정). 서버 렌더(공유 랜딩)는 파일 존재로, 브라우저는 onError로 판단.
- 한쪽이라도 출생시간이 없으면 시주 쌍은 비교하지 않고, 종합 궁합 카드와 공유 랜딩에 고지한다.
- 문답 페이지는 5문항을 최대로 두고 문항 수를 고르게 나눈다(6→3+3, 7→4+3, 8→4+4, 9→5+4, 10→5+5).
- AI 해석 글은 **관계 유형별로** 저장한다(프로필×2 → `compatibilities.narratives[relation_type]`, 직접 입력 → 서버 메모리) — 같은 쌍·같은 유형은 다시 만들지 않고, 서버는 같은 요청의 동시 생성을 하나로 나눠 준다(2026-10-23). 프롬프트가 바뀌면 `NARRATIVE_PROMPT_VERSION`을 올린다. 괄호 밖에 남은 한자는 서버가 "한글(漢字)"로 바꿔 보낸다.

**하지 않는다**
- 인트로·문답 제출 직후 화면에서 **일치율을 보여주지 않는다** — 풀이를 읽기 전에 김새지 않게, 탭을 끝까지 넘기게 (2026-10-13 분석, 2026-10-15 궁합 결정).
- 문답 답을 **서버에 보내지 않는다**(저장 여부 미정). 공유 카드에도 넣지 않는다(ROADMAP V3 메모).
- 프론트에서 궁합 해석 문장을 **새로 만들지 않는다**. 지금 남아 있는 `summarize*`·신살 의미 표는 부채이고 늘리지 않는다(REFACTORING §4-2). 관계 종류 이름표(상생·상극·비화) 같은 표시용 이름까지만.
- 새 행동 이벤트를 추가하지 않는다(2026-09-28).
- 한눈에 탭을 다시 만들지 않는다. `summary`는 LLM 기본 요약용 API로만 남긴다(2026-10-15).
- 두 분의 캐릭터 카드에는 "확인하기" 게이트를 두지 않는다 — 인트로에서 이미 공개한 내용(2026-10-17).

## 5. 수용 기준

인트로
1. 새 결과를 받으면 주소가 `?step=intro`가 되고 "두근두근 💓" 화면에 두 사람 캐릭터 실루엣 둘(각각 "?"가 겹침)과 ♥가 뜬다. [건너뛰기]를 누르면 `?tab=character` 성격 탭이다.
2. [💞 두 분의 궁합 확인하기] → 약 1.2초 뒤 캐릭터 상자(두 사람 사주 캐릭터 그림·칭호·점수·라벨·역할 칩 2개·설명)와 까치 인사가 보이고, 문답이 있으면 버튼이 둘, 없으면 [💞 궁합 분석 보기] 하나다.
3. 문답 화면에서 브라우저 뒤로 가기를 하면 드럼롤 없이 인트로의 인사 화면으로 돌아온다.
4. `?tab=domain` 같은 주소를 새로고침하면 인트로 없이 그 탭이 바로 보인다.

문답
5. 문항이 N개면 머리에 "1/⌈N/5⌉ 페이지 · 0/N 답함"이 보이고, 첫 페이지에는 Q1부터 ⌈N/페이지수⌉개만 있다(8문항이면 Q1~Q4).
6. 그 페이지 문항을 다 고르기 전에는 아래 버튼이 비활성이고 "이 페이지에 m개 남았어요"다. 다 고르면 "다음 문항으로 (a~b번) ›"로 바뀌고 눌린다.
7. 다음을 누르면 다음 페이지 첫 문항이 보이고 화면이 카드 머리로 올라간다(전체 화면에서는 스크롤 0, 탭에서는 고정 탭바 아래). "‹ 이전 문항 (a~b번)"으로 돌아가도 고른 답이 그대로다.
8. 마지막 페이지에서 전부 답하면 [🔮 사주 예측과 맞춰 보기]가 활성. 인트로 흐름에서 누르면 "답변 완료!"만 보이고 일치율은 없다. 설문조사 탭에서 보면 일치율 %·까치 해설·문항별(다른 문항 먼저, 근거는 다른 문항에만)이 보인다.
9. 인트로에서 1페이지만 답하고 [분석 바로 보기 ›]로 나간 뒤 설문조사 탭을 열면 2페이지부터 보인다. [다시 답하기]를 누르면 1페이지로 돌아가고 답이 모두 지워진다.

탭
10. 프로필×2면 탭이 7개(4+3 두 줄)이고, 직접 입력·혼합·초대면 6개 한 줄에 시운 탭이 없다. 문답이 없는 옛 결과면 설문조사 탭도 없다.
11. 성격 탭의 카드 순서는 두 분의 캐릭터 → 신살 → 신강·신약이고, 팔자비교 탭은 팔자비교 → 오행 보완이다. 팔자비교 카드 안은 까치 팁 → 팔자 그림 → (그림 아래 까치 팁) → 일주(日柱) 관계 3칸(천간합·육합·충 중 하나라도 있을 때만) → 삼합 완성(있을 때) 순이다.
12. 팔자비교 탭이 열릴 때 팔자 그림의 기둥이 시→일→월→년 순서로 나타나고 합·충 배지가 뒤따른다. 인트로가 덮여 있는 동안에는 재생되지 않는다.
13. 두 분의 캐릭터 카드는 버튼 없이 바로 보이고, 까치 팁 "○○님은 이모지 **역할**, ○○님은 이모지 **역할** — … 사이예요" 아래 상자(두 사람 사주 캐릭터 그림·칭호·역할 칩 — "관계 유형 · 두 분은" 줄·점수·설명은 없다)가 있고, 그 아래 까치 팁에 설명 문장(이름 채움), 그 아래 "잘 맞는 순간" 3개 \| "부딪히기 쉬운 순간" 3개 칩이 두 칸으로 있다(인트로 상자는 반대로 점수·설명이 상자 안에 있고 칩·설명 팁이 없다). 그림은 왼쪽이 첫 번째 분, 오른쪽이 두 번째 분, 가운데 ♥. 그림 파일이 없는 쪽만 역할 이모지.
14. 탭을 바꾸면 주소의 `tab`만 바뀌고 `invite`·`p1`·`p2`는 남는다. 전체 새로고침이 일어나지 않고, 아래로 내려 읽던 중이었다면 새 탭 첫 줄이 탭바 바로 아래로 올라온다.
15. 모든 탭 끝에 다음 이야기 카드가 있고 제목은 3-3 표의 hook과 같다. AI 해석 탭의 다음은 첫 탭 성격이다. 문답을 제출한 뒤에는 설문조사 탭의 hook이 "답해 둔 설문조사, 사주와 몇 % 맞았을까?"다.
16. 종합점수 탭에는 종합 궁합 카드가 없고 레이더와 영역 카드 4개만 있다. 영역 카드는 항상 연애·결혼·재물·직업 순(이름은 관계별 표시 이름).
17. 시운을 못 받으면 "시운을 불러오지 못했어요. 잠시 후 다시 열어 보세요."가 보인다. 받으면 오늘·내일·모레·글피 탭(기본 오늘), 일진 색 히어로(한 줄·함께 할 것·피할 것·간지·궁합 점수), 두 분 각자의 그날 타일 둘, 영역 막대 4개, 레벨 배지, 주간 궁합 시운 7줄과 함께하기 좋은 날 3개가 보인다. 내일 탭을 누르면 날짜·점수가 바뀌고 문장의 "오늘"이 "내일"로 바뀐다.
18. Ollama가 꺼져 있으면(`/narrative`가 503) AI 해석 탭에 "AI 종합해석은 까치 서버(Ollama)가 켜져 있을 때 제공돼요…" 팁이 보인다.
21. 프로필×2 결과를 한 번 끝까지 받은 뒤 같은 쌍·같은 관계 유형으로 다시 열면 AI 해석 탭에 글이 바로 있고 `/narrative` 요청이 나가지 않는다.
22. AI 해석 글은 두 분은 이런 사이 → 끌리는 순간 → 티격태격 포인트 → 서로에게 주는 것 → 영역별 궁합 → 함께하면 운이 트이는 것 여섯 섹션이고 한 줄 총평이 없으며, 두 사람을 "○○님"으로 부르며("첫 번째 분" 없음) 괄호 밖에 한자가 없다.

헤더·공유
19. 결과 헤더의 [공유]는 `/s/{id}` 링크를 만들고, 공유 문구는 캐릭터가 있으면 "○○님과 ○○님은 {칭호}! 궁합 N점…"이다. [다시 입력]은 폼으로 돌아가고 주소에서 `step`·`tab`이 빠진다.
20. 궁합 상담 FAB는 결과가 있을 때만 보이고, 누르면 `/compatibility/chat`이다.
