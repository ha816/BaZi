## 1. 목적

아침에 홈을 열면 **까치가 오늘 소식 하나를 물어다 준다** — 내 캐릭터가 오늘 한 문장과 한 행동을 건네고, 그 아래 내가 아끼는 사람들의 오늘이 얼굴로 보인다. 더 보고 싶으면 시운·궁합·분석으로 간다.

지키는 원칙
- **한 문장 + 한 행동이 먼저, 점수는 보조**(R4). 점수 그래프·영역 점수는 홈에 두지 않는다 — 시운 화면 몫. 다만 시운의 "이 시간대가 좋아요"·"주간 시운" 두 카드는 오늘의 나 바로 아래에 고정으로 둔다(2026-10-26 사용자 결정).
- **내 오늘은 한 덩어리로 가장 크게.** 같은 모양 카드를 사람 수만큼 반복하지 않는다.
- **길조 까치 톤.** 반가운 소식이 먼저, 주의는 ✕ 한 줄. 공포·결핍·손실 회피 문구 금지.
- 해석 문장·점수는 전부 백엔드. 프론트는 표시만.
- 폰(390px) 기준 스크롤 세 화면 이내.

## 2. 진입과 상태

- 로그인 판단은 `localStorage["kkachi_member_id"]`. 로그인 없이도 열린다.
- 홈은 주소 파라미터를 쓰지 않는다(`?tab=`·`?step=` 없음). 알림 진입은 지금처럼 `/siun?src=push`로 가고 홈과 무관하다.

| 상태 | 보이는 것 |
|---|---|
| 비로그인 | **내 캐릭터 찾기 히어로**(§3-4) → 퀵스타트 폼 → 오늘의 띠 → 까치 소식(§3-5) → 소개 영상 |
| 로그인 · 프로필 없음 | "내 사주를 등록하면 까치가 매일 아침 소식을 물어다 줘요" 카드 + [내 사주 등록] → `/profile` |
| 로그인 · 기본 프로필만 | ① 오늘의 나 → ② 오늘 내 사람들(빈 줄: "+ 사람 추가" 한 칸과 "궁금한 사람을 추가하면 오늘 둘의 궁합을 알려 줘요") → ③ 까치 소식 |
| 로그인 · 여러 프로필 | ① → ②(기본 프로필을 뺀 사람들) → ③ 까치 소식 |
| 불러오는 중 | ①의 자리·크기를 그대로 둔 스켈레톤(그림 원·말풍선 세 줄) + ② 얼굴 원 3개. 레이아웃이 밀리지 않는다 |
| 묶음 API 실패 | ① 자리에 "까치가 소식을 가져오지 못했어요" + [다시 시도]. ②③은 숨긴다 |

- **기본 프로필** = `is_self` 프로필(CLAUDE.md "기본 프로필"). ①은 항상 기본 프로필이다. 다른 사람의 오늘은 ②에서 그 사람을 눌러 간다.
- **이벤트**: `home_view{logged_in, profiles?}`(지금과 같음). 새 이벤트는 열린 결정(§6).

### 2-1. 묶음 API `GET /members/{member_id}/home`

홈이 부르는 백엔드는 이것 하나다. 회원이 없으면 404, 기본 프로필이 없으면 `me: null`·`next: []`(사람들의 `compat`도 null). 구현 `application/home_service.py` `HomeService.get_home`(2026-10-24), 로컬 측정 캐시 hit 약 70ms(첫 호출 250ms).

```
{
  date: "2026-10-24",
  me: {
    profile_id, name,
    character: { key, art_key, title, line },              // build_saju_character(natal) — 분석 결과의 natal.character와 같은 값
    week: [{ date, total_score, level, weather }] ×7,      // 오늘부터 7일(get_forecast 그대로) — "이 시간대가 좋아요"(오늘~글피 weather.hours)·"주간 시운" 카드 (2026-10-26)
    zodiac_branch: "巳",                                    // 내 년지(띠) — ③ 오늘의 띠에 "나" 표시 (2026-10-26)
    fortune: { headline, action, caution, total_score, level, day_element,
               solar_term, son_eomneun_nal }                // FortuneService.get_forecast(7일)[0] (fortunes 캐시)
  } | null,
  people: [                                                 // 기본 프로필을 뺀 나머지, 최근에 추가한 사람 먼저
    { profile_id, name,
      character: { key, art_key },
      marks: { sinsal: ["문창귀인", …], sipsin: ["正印", …] },  // 가진 신살(한글)·십신(한자), 중복 없음 — §3-2 사주 한 입 (me에도 같은 필드, 2026-10-26)
      compat: { score, level, headline } | null }           // compute_daily_compat(나, 그 사람, 오늘) — level 좋음·보통·주의, me 없으면 null
  ],
  today: { … },                                             // §3-5 까치 소식 — GET /kkachi/today와 같은 값, 기본 프로필이 없어도 있음
  next: [                                                   // §3-3 후보 — 화면 노출 없음(2026-10-26 ③ 제거), API에는 남겨 둠
    { kind: "good_day", date, action }                      // 내일~6일 뒤 중 level "좋은 날" 첫 날
    { kind: "compat", profile_id, name }                    // 올해 compatibilities 캐시가 없는 첫 사람
    { kind: "ai_report" }                                   // 올해 analyses에 지금 프롬프트 버전 AI 풀이 없음
  ]
}
```

- 캐릭터·오늘의 궁합은 사람마다 **natal만** 계산한다(`KkachiService.analyze_natal`, 한 사람 1ms 미만 — 대운·세운까지 하는 analyze의 1/40). analyses 캐시를 읽거나 쓰지 않는다(2026-10-24 구현 때 결정 — 처음 적은 "캐시에서 꺼내고 없으면 저장"보다 단순하고 빠르다).
- 나의 natal은 요청마다 한 번만 만든다. 사람마다 `/compatibility/daily`를 부르지 않고 `compute_daily_compat`를 직접 쓴다.
- 나의 운세는 앞으로 7일을 한 번에 받는다 — 0번이 ①, 나머지가 `good_day` 후보. 날씨(외부 호출 약 1초)는 날씨까지 든 캐시가 없는 날이 있을 때만 받는다(`FortuneService.get_forecast`, 2026-10-24).
- `art_key`는 `character_art_key(key, is_male)` — 여성 프로필은 `{key}_여`.
- 다른 회원의 프로필은 섞이지 않는다(`member_id` 소유만).

## 3. 화면 구성과 순서 (로그인)

### 3-1. ① 오늘의 나

카드 하나 — 다른 홈 카드와 같은 틀(`FEED_CARD`: 흰 바탕·얇은 테두리·rounded-2xl, 2026-10-26). 카드 안 맨 윗줄 제목 "오늘의 나". 오늘 일진 오행 색은 `{day_element}의 날` 배지 바탕에만(`ELEMENT_META[day_element]`의 연한 색), 말풍선은 상아색.

1. [오늘 시운 자세히 →] 버튼 바로 위 줄(2026-10-26 제목 아래에서 옮김) — 작은 배지들: 레벨(`FORECAST_LEVEL_META[level]`) · `{total_score}점` · `{오행 이모지} {day_element}의 날` · 절기(있을 때) · 👻 손없는 날(있을 때). 홈에는 날짜 머리줄이 없다(2026-10-26 제거)
2. 본문 — 왼쪽 내 캐릭터 그림(정사각 원형 프레임, `charArtSrc(art_key, key)` → 유형 그림 → 오늘 레벨 까치 폴백), 오른쪽 **까치 말풍선**: `headline`(가장 큰 글씨) → `✦ {action}` → `✕ {caution}`(빈 문자열이면 줄 자체 없음). `MorningBrief`와 같은 문장
3. 그림은 움직이지 않는다(2026-10-26 둥실 애니메이션 제거). 그림 아래 한 줄 — 캐릭터 `title`(예: "든든한 수호자"). 캐릭터가 없으면 그림 자리에 기본 까치, 이 줄 없음
4. 버튼 — [오늘 시운 자세히 →] `/siun` 한 줄 폭. 홈에는 공유 버튼을 두지 않는다(2026-10-26 — 번잡해 보여서; 시운 공유는 `/siun` 헤더에서)

### 3-1b. 오늘의 띠 · 이 시간대가 좋아요 · 주간 시운 (2026-10-26)

**주간 시운 · 이 시간대가 좋아요는 ① 오늘의 나 카드 안 하단**(배지 줄 아래, [오늘 시운 자세히 →] 위, 구분선으로 나눔 — 2026-10-26, 처음엔 따로 카드였다). 순서는 주간 시운(3일) → 이 시간대가 좋아요. `embedded`로 테두리 없이 소제목 크기. ① 다음 카드는 **오늘의 띠**(`TodayZodiacCard`, 비로그인은 까치 소식 맨 앞). 시운 화면(오늘 탭)과 같은 컴포넌트 `components/SiunCards.tsx`(`HourlyLuckCard`·`WeeklySiunCard`)를 쓴다 — 고치면 두 화면이 같이 바뀐다.
- **이 시간대가 좋아요** — 오늘(지금 2시간 전부터)~글피의 3시간 간격 날씨 오행 가로 줄. 용신과 같은 오행 = 초록 "최고", 용신을 생하는 오행 = 주황 "좋음". 데이터 `me.week[0..3].weather.hours` + `me.fortune.yongshin`. 시간대가 하나도 없거나, **오늘** 남은 시간대(지금 2시간 전부터)에 최고·좋음이 하나도 없으면 홈에서는 카드 없음(2026-10-26 — 내일 이후만 좋은 날은 숨김. 시운 화면은 늘 보임, `needGoodToday`)
- **주간 시운** — 오늘부터 **3일**(2026-10-26 7일 → 3일, 시운 화면은 7일 그대로 `count`) 한 줄씩: 날짜·날씨 이모지·날씨·오행·기온·운세 점수·레벨 아이콘. 날씨 없는 날은 줄 없음

### 3-2. ② 오늘 내 사람들

둥근 카드 하나 — 카드 안 윗줄에 제목 "오늘 내 사람들" + 오른쪽 작은 링크 [관리] → `/profile`(2026-10-26 카드로 감쌈).

- 가로 스크롤 줄. 한 칸 = 캐릭터 얼굴(원형 64px) + 이름 + 오늘 궁합 배지
- 배지: `compat.level` — 좋음 ♥ / 보통 · / 주의 ! 를 레벨 색(좋음 emerald · 보통 slate · 주의 amber)으로, 숫자는 쓰지 않는다
- 칸을 누르면 `/compatibility?p2={profile_id}`(첫 번째 분은 기본 프로필 기본값)
- 줄 끝 칸 "+ 사람 추가" → `/profile`. 프로필이 10개면 이 칸 없음
- 얼굴 줄 아래 한 줄: 오늘 궁합이 가장 좋은 사람의 `headline`을 "{이름}님과 — {headline}"으로(좋음인 사람이 없으면 이 줄 없음)

- **사주 한 입**(2026-10-26 — 까치 소식에서 이 카드 안으로): 얼굴 줄 아래 구분선 → 오늘의 신살·십신 하나(그림·이름(한자)·한 줄·설명, §3-5와 같은 19일 순번) → "{문창귀인(文昌貴人)}, 내 사람들에게도 있을까?"(사람이 없으면 "나에게도 있을까?") [확인하기 →]. 누르면 그것을 가진 사람 얼굴에 금테·✦ 배지, 결과 줄 "✦ 이소민님·강이경님에게 있어요. 나에게도 있어요!". 판정은 홈 응답 `marks`(신살 한글 이름 = `SINSAL_INFO` 키, 십신 한자 = `SIPSIN_INFO` 키). 확인 상태는 저장하지 않는다(새로 열면 다시 질문)

### 3-3. (옛 ③) 이어서 할 것 — 화면에서 뺌 (2026-10-26, 자리는 §3-5 까치 소식이 이음)

홈을 덜 번잡하게 하려고 섹션을 없앴다. 아래 표는 묶음 API `next`가 지금도 계산하는 후보의 기록이다(되살리거나 다른 자리에 쓸 때 참고). 알림 켜기는 `/siun`의 `PushSubscribeButton`에 그대로 있다.

| 순서 | kind | 조건 | 카드 | 누르면 |
|---|---|---|---|---|
| 1 | `push` | 클라이언트 `getPushState() == "off"` | "내일 아침 7시, 까치가 먼저 알려 드릴까요?" | 그 자리에서 알림 켜기(`PushSubscribeButton`과 같은 동작), 켜지면 카드 사라짐 |
| 2 | `good_day` | 서버: 나의 앞으로 7일 중 `level == "좋은 날"`인 첫 날이 내일 이후 | "{M}월 {D}일 {요일}이 좋은 날이에요" + 그날 `action` (날짜를 함께 — 토요일에 "이번 주 월요일"이라 하지 않게) | `/siun` |
| 3 | `compat` | 서버: ②의 사람 중 올해 `compatibilities` 캐시가 없는 첫 사람 | "{이름}님과 궁합을 아직 안 봤어요" | `/compatibility?p2={id}` |
| 4 | `ai_report` | 서버: 기본 프로필 올해 analyses에 지금 프롬프트 버전 `ai_report` 없음 | "까치가 쓴 내 사주 이야기, 한 편 읽어 볼래요?" | `/analysis?tab=ai` — 기본 프로필이 골라진 폼, [분석 시작] 한 번이면 AI 풀이 탭 |

### 3-5. ③ 까치 소식 (2026-10-26)

②(비로그인은 퀵스타트 폼) 아래 카드 세 장까지, **종류마다 한 장**. 칸 소제목은 없다 — 카드마다 안에 제목(2026-10-26). 재미와 새소식을 나누는 자리 — 매일 바뀐다.

1. **오늘의 띠** — "오늘은 {계유}({癸酉})일 — {검은} {닭}의 날"(천간 오행 색: 木 푸른·火 붉은·土 누런·金 흰·水 검은) + 12띠 격자(6×2, 子부터). 칸 색은 오늘 일지와의 관계: 삼합·육합 초록 "기운 받는 띠", 충·원진 주황 "조심할 띠", 같은 띠 금색 "오늘의 주인공". 기본 프로필이 있으면 내 띠 칸에 "나" 배지. **띠별 한 줄**(2026-10-26, 옛 신문 띠별 운세): 칸을 누르면 그 띠의 "{🐍 뱀띠} · 65·77·89·01·13년생" + 한 줄 충고(백엔드 `zodiac[].advice` — 그 띠와 오늘 일지의 관계(나·삼합·육합·충·원진·보통)별 4문장을 날짜·띠 순번으로 돌림. 문장은 관계의 전통 의미에 기대 씀, 근거·출처 `docs/research/home_홈화면.md` §6). 처음엔 내 띠(없으면 오늘의 띠)가 골라져 있다 — 화면에서는 ① 바로 다음(§3-1b)
2. **사주 한 입** — 오늘~3일 뒤에 절기가 있으면 절기 카드("내일은 입동(立冬)" + `SOLAR_TERMS` 팁)는 까치 소식에. 상식 카드는 **로그인이면 ② 오늘 내 사람들 카드 안**(§3-2, 2026-10-26), 비로그인만 까치 소식에: 만세력 섹션의 신살 9종(`SINSAL_INFO`)·십신 10종(`SIPSIN_INFO`)을 날짜 순번으로 하나씩(19일 주기) — 그림·이름(한자)·한 줄·설명 + [내 사주에도 있을까? →] `/analysis`. 손없는 날이면 카드 아래 👻 한 줄
3. **새소식** — 코드 안 목록 `KKACHI_NEWS`(`app/page.tsx`, 맨 위가 최신)에서 오늘로부터 30일 안의 가장 최근 하나. 없으면 카드 없음. 누르면 그 기능 화면으로. 운영자가 맨 위에 한 줄 더하면 올라간다 — **맨 아래**(2026-10-26). 보여 줄 소식이 없는 때가 많을 수 있어 노출 조건은 열린 결정(§6)

`GET /kkachi/today`(로그인 불필요) = `fortune_rules.build_today(오늘)`:

## 4. 규칙

**한다**
- 백엔드 호출은 로그인 홈에서 `GET /members/{id}/home` 1회. 비로그인은 `GET /kkachi/today` 1회(2026-10-26 — 까치 소식; 실패하면 그 칸만 숨김. 위치 감지 `ipapi.co`는 퀵스타트 폼이 쓰던 대로).
- 문장은 백엔드가 준 그대로(`headline`·`action`·`caution`·`compat.headline`·`today.zodiac[].advice`). 까치 소식의 새소식·사주 한 입은 표시용 콘텐츠(공지 목록·만세력 표시 메타)라 프론트에 둔다. 이름 접두(`{name}님, `)도 백엔드 것.
- 캐릭터 그림은 `art_key` → 유형 키 → 까치 그림 순 폴백(히어로는 오늘 레벨 까치, 사람 줄은 기본 까치). 그림이 없어 칸이 비지 않는다.
- 렌더되지 않는 옛 코드(`WeatherPost`·`HourlyRow`·`getWeather` import·`weatherCity`·StoryTray `activeId`)는 이 개편에서 지운다.

**하지 않는다** (2026-10-24 결정)
- 영역 점수 막대·그래프를 홈에 두지 않는다 — 시운으로. (주간 시운 7일 목록은 2026-10-26부터 홈에 둔다 — §3-1b)
- 스트릭·연속 일수·"놓치면 사라져요" 같은 손실 회피 문구(R4 결정 유지).
- 설문을 홈에 두지 않는다(V3 — 홈 퀵스타트 "30초 만에 내 사주"를 지킨다).
- 사람마다 같은 모양의 큰 카드를 반복하지 않는다. 다른 사람은 ②의 얼굴 칸으로만.
- 점신식 "조심할 것"을 히어로 첫 줄로 올리지 않는다 — 첫 줄은 항상 `headline`.
- 프론트에서 레벨·점수로 문장을 고르지 않는다(해석 분기 금지).

## 5. 수용 기준

390px, 로그인 + 프로필 4개(기본 1 + 3) 기준. 따로 적은 것만 다른 상태.

1. 홈 진입 시 브라우저가 부르는 백엔드 요청은 `/members/{id}/home` 1회다(`/forecast`·`/daily`·`/compatibility/daily`·`/profiles` 목록 호출이 없다).
2. 첫 화면(스크롤 전)에 ① 오늘의 나 카드가 통째로 보이고, 그 안 가장 큰 글자는 `headline`이다. 점수 숫자는 윗줄 배지 안에만 있다.
3. `caution`이 빈 문자열인 날은 ✕ 줄이 없다.
4. ① 카드는 ②·까치 소식 카드와 같은 흰 둥근 카드이고 안에 제목 "오늘의 나"가 있다. 오늘 `day_element` 오행 색은 `{day_element}의 날` 배지에만 있다(예: 火 날이면 붉은 계열).
5. 기본 프로필이 여성이면 그림 주소가 `saju_character/{key}_여.webp`이고, 그 파일이 없으면 `saju_character/{key}.webp`, 그것도 없으면 오늘 레벨의 까치 그림(좋은 날 `good_kkachi.webp` · 평범한 날 `normal_kkachi_00.png` · 주의 `caution_kkachi.webp`)이 보인다.
6. ②에 얼굴 칸 3개 + "+ 사람 추가" 한 칸이 가로로 있고, 칸마다 이름과 궁합 배지(♥ / · / !)가 있으며 숫자는 없다.
7. ②의 칸을 누르면 `/compatibility?p2={그 프로필 id}`로 간다.
8. ② 아래에 "이어서 할 것" 카드 묶음이 없다(2026-10-26).
9. ① 오늘의 나에 [공유] 버튼이 없고 [오늘 시운 자세히 →] 하나만 있다(2026-10-26).
10. ① 바로 아래에 "이 시간대가 좋아요"(오늘 남은 시간대에 최고·좋음이 있을 때만)·"주간 시운" 카드가 차례로 있고(시운 화면과 같은 모양), 화면 어디에도 영역 점수 막대·연속 일수가 없다.
11. 비로그인 홈은 백엔드 요청 없이 그려지고, 맨 위 카드 제목이 "나는 어떤 캐릭터일까?"이며 바로 아래에 이름·생년월일 폼이 있다. 폼 제출 후 `/analysis?step=intro`에서 자동 분석된다.
12. 로그인 · 프로필 없음이면 "내 사주 등록" 버튼이 보이고 누르면 `/profile`로 간다.
13. 로그인 · 기본 프로필만이면 ②에 "+ 사람 추가" 한 칸과 안내 문장만 있다.
14. 불러오는 동안 스켈레톤이 ① 카드와 같은 높이를 차지해, 데이터가 들어와도 아래 내용이 밀리지 않는다.
15. 백엔드 테스트(`tests/application/test_home_service.py`·`tests/adapter/test_profile_controller.py`, 2026-10-24 통과): `GET /members/{id}/home`은 다른 회원의 프로필을 돌려주지 않고, 기본 프로필이 없으면 `me: null`·`next: []`, 회원이 없으면 404다. 여성 프로필의 `art_key`는 `{key}_여`, `good_day`는 오늘이 아닌 내일 이후 첫 좋은 날, 옛 프롬프트 버전 AI 풀이는 없는 것으로 친다.
16. ①·②·까치 소식은 모두 둥근 카드이고 카드 밖에 칸 제목이 없다. ② 아래 까치 소식 카드가 3장 이하이고 종류(새소식·오늘의 띠·사주 한 입)마다 1장이다. 오늘로부터 30일이 지난 새소식만 있으면 새소식 카드가 없다.
17. 오늘의 띠 카드에 12띠가 子부터 6×2로 있고, 기본 프로필의 띠 칸에만 "나" 배지가 있다. 칸을 누르면 그 띠의 년생·한 줄(`advice`)이 나오고, 12띠 관계를 풀어 쓴 종합 문장은 없다.
18. 오늘~3일 뒤에 절기가 있으면 사주 한 입 자리에 절기 카드가, 없으면 신살·십신 상식 카드가 있다(백엔드 테스트: 입동 11-07 기준 11-04는 `days: 3`, 11-03은 `null`).
19. 비로그인 홈도 퀵스타트 폼 아래에 까치 소식 칸이 있고, 백엔드 요청은 `/kkachi/today` 1회다.
20. 로그인 홈의 사주 한 입은 ② 카드 안 얼굴 줄 아래에 있고 까치 소식에는 없다. [확인하기]를 누르기 전엔 얼굴에 표시가 없고, 누르면 그 신살·십신을 가진 사람(`marks`) 얼굴에만 금테·✦가 생기며 "✦ {이름}님·…에게 있어요"(없으면 "오늘 내 사람들 중엔 없어요") + "나에게도 있어요!/나에게는 없어요"가 나온다.
