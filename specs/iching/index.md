## 1. 목적

타로가 "오늘 한 장"으로 아침 의식을 맡았으니, 주역은 **"지금 이 고민"에 답하는 질문 괘**다. 질문 하나 → 동전 셋을 여섯 번 → 본괘(지금 한 줄) → 변효가 있으면 지괘(앞으로 한 줄) → 영역 한 줄 → 사주가 있으면 오늘 일진·내게 필요한 기운과의 교차 두 문장. 괘가 답이고 사주는 배경 — 두 체계의 길흉을 더하지 않는다. 그림 자산 0(괘는 선 여섯 줄 CSS), 원문은 퍼블릭 도메인이되 **문장은 전부 우리가 쓴다**(한자는 괘 글자 괄호 안에만). LLM·DB 없이 룰 문장만으로 가치가 서야 하고, 4주 측정(§5 밖, ROADMAP)으로 확인돼야 V11-2로 간다.

## 2. 진입과 상태

| 상태 | 요청 | 보이는 것 |
|---|---|---|
| 로그인, 기본 프로필 있음 | `POST /iching/ask {question, category?, member_id}` | 괘 + 영역 + **교차 두 문장**(`cross`) |
| 로그인, 기본 프로필 없음 | 같은 요청 → `identity:"date"`, `cross:null` | 괘 + 영역 + "기본 프로필을 정하면 오늘 일진·내게 필요한 기운과 함께 봐요" → `/profile` |
| 비로그인, `/analysis` 입력값 있음 | `{question, category?, birth_dt, gender[, hour_unknown, city]}`(sessionStorage `kkachi_analysis_input`) | 로그인과 같음 |
| 비로그인, 입력값 없음 | `{question, category?}` | 괘 + 영역 + "내 사주를 먼저 보면 …" → `/analysis` |
| 위기 신호 질문 | 어떤 상태든 | 괘 없이 안내 문장 + 전화번호 두 개(109·1577-0199, `tel:` 링크) + [돌아가기] |

- 로그인 불필요(`/tarot`·`/zodiac`·`/stars`와 같은 정책). 하단 메뉴에 칸을 더하지 않는다 — 진입은 홈 까치 소식의 **"까치에게 묻기" 카드**(카드 전체가 링크, 제목 줄 오른쪽 "자세히 →")와 새소식(30일).
- 백엔드 호출은 질문마다 **한 번**. 저장 없음 — 같은 사람·같은 날·같은 질문(공백·끝 물음표 무시)은 같은 괘(seed). "다시 뽑기" 없음, [다른 것 묻기]만.
- 이벤트: `iching_view{page:"iching", logged_in}` · `iching_ask{category, len, has_saju, mode}`.

```
POST /iching/ask  { question(4~80자), category: 연애|일|재물|기타|null, member_id? | birth_dt?&gender?&hour_unknown?&city? }   (로그인 불필요)
→ { date, identity: person|date, question(정규화), category(없으면 질문에서 감지),
    values[6](6 노음·변함 / 7 소양 / 8 소음 / 9 노양·변함, 아래→위), mode: still|one|many,
    hexagram{ id 1~64, key hex_NN, name(쉬운 이름), hanja, traditional(중천건), upper{name,hanja,element}, lower{…}, keywords[3], lines[6]{yang,changing}, line(지금 한 줄) },
    transformed{ …같은 꼴, lines는 변효를 뒤집은 것, line(앞으로 한 줄) } | null,
    change(변효 머리 문장 — 없음/1개/2개 이상), area{label, text} | null(기타), cross(두 문장) | null }
→ 위기 신호면 200 { blocked:"crisis", message, helplines[2]{name, number} }   · 길이 밖·모르는 영역 422
```
- `member_id`가 있으면 그 회원의 기본 프로필(`is_self`), 없으면 `birth_dt&gender` — 둘 다 없거나 기본 프로필이 없으면 `identity:"date"`(404 아님). 사주가 있으면 `analyze_natal`로 용신, `compute_fortune`(날씨·대운 없이)으로 오늘 레벨.

## 3. 화면 구성과 순서

`PageHeader` 제목 "까치에게 묻기", 설명 "고민 하나를 적으면 동전 셋을 여섯 번 던져 주역(周易) 괘를 뽑아요". 카드 한 장이 상태에 따라 바뀐다.

1. **질문 카드** — "무엇이 궁금한가요?" + 두 줄 입력칸(80자, 아래 오른쪽 "n/80", 왼쪽은 4자 전 "4자 이상 적어 주세요" / 뒤 "할까 말까, 언제가 좋을까 같은 물음이 잘 맞아요") → 영역 칩 연애·일·재물·기타(하나 고르거나 안 고름 — "고르지 않으면 질문을 보고 정해요") → [괘 뽑기](4자 전·요청 중 비활성, 요청 중 "동전을 꺼내는 중…") → 작은 글 "같은 날 같은 질문은 같은 괘가 나와요. 다시 뽑기는 없어요."
2. **뽑는 중**(답이 온 뒤 약 2.9초) — 질문을 따옴표로 맨 위에 → 동전 셋(앞면 금색·뒷면 상아색, 480ms마다 뒤집힘, 앞면 수 = 값 − 6) → 그 아래 괘 그림에 **아래부터 한 줄씩** 쌓임(`hex-line-drop`) → "n번째 줄 · 양/음(· 움직임)". 움직임 줄이기 설정이면 바로 완성 화면.
3. **완성 화면**(`score-pop`) — 쉬운 이름(괘 글자) 크게("싹 트기 전(屯)") → "3번째 괘 수뢰둔 · 위 물(坎) 아래 우레(震)" 작은 회색 → 키워드 칩 3 → 상아색 상자 **지금**(본괘 한 줄) → 상자 **앞으로**(변효가 있으면 지괘 작은 그림 + 이름(글자) + "N번째 괘 …" 한 줄, 그 아래 `change` + 지괘 한 줄 / 없으면 `change`만 "움직이는 줄이 없어요. …") → 영역 한 줄(연애·일·재물 — 기타는 없음, dt/dd) → 사주가 있으면 상아색 상자 "오늘 일진과 함께 보면, {첫 문장}." / "{둘째 문장}."(타로와 같은 표기 — 문장마다 줄바꿈, 굵게·가운뎃점 없음) / 없으면 안내 한 줄(§2) → 면책 한 줄 → [다른 것 묻기](질문 카드로).
4. 맨 아래 [← 홈으로].

괘 그림(`HexagramFigure`): 양은 한 줄, 음은 두 토막, 아래→위. 변효는 **금색**이고 오른쪽에 ○(노양 9)·×(노음 6). 지괘 그림은 작게, 변효 표시 없음.

## 4. 규칙

**뽑기(`iching_rules.ask`)**
- identity = `"{birth_dt:%Y-%m-%dT%H:%M}|{gender}"`(타로와 같음 — 프로필·직접 입력 동일), 없으면 `""`. `seed = sha256("kkachi-iching-v1|{identity}|{YYYY-MM-DD}|{정규화 질문}")[:8]`. 정규화 = 공백 하나로 + 끝 `?!.。` 제거.
- 3동전법: 효마다 동전 셋(앞 3·뒤 2) 합 6/7/8/9 = 1/8·3/8·3/8·1/8. 변효(6·9)는 효당 1/4, 여섯 줄에 평균 1.5개, 없음 ≈ 18%.
- 변효 읽기(리서치 §3, 단순 규칙): 0개 `still` → 본괘만 + "움직이는 줄이 없어요. {이름}의 흐름이 한동안 그대로 이어지니 …" / 1개 `one` → "아래에서 n번째 줄이 움직여 {지괘 이름}(으)로 바뀌어요." + 지괘 `next` / 2개 이상 `many` → "줄 k개가 한꺼번에 움직여 크게 바뀌는 중이에요. {지괘 이름}(으)로 가요." + 지괘 `next`. 주희 규칙은 쓰지 않는다.
- 영역: 칩이 있으면 그것, 없으면 질문 낱말로 연애 → 재물 → 일 순 감지(`_CATEGORY_WORDS`, "일" 한 글자는 안 씀), 아니면 기타. 영역 문장은 **본괘**의 연애·일·재물 중 하나, 기타는 없음. 칩은 영역 문장만 바꾸고 괘는 그대로(seed에 안 들어감).

**문장**
- 64괘 × (쉬운 이름·키워드 3·지금 `now`·앞으로 `next`·연애·일·재물) + 팔괘 8(쉬운 이름·글자·오행). **전부 한글**, 괘 글자는 `hanja` 필드에만(`test_iching_rules`가 검사 — 한자·영문 0, hanja는 한자 1~2자). 까치 말투 "~해요", 괘의 그림(상)을 한 번씩 부르고 괘를 바꿔도 성립하는 두루뭉술한 문장은 피한다. `next`는 "앞으로"로 시작.
- 이름 표기는 **쉬운 뜻 이름(괘 글자)** — "하늘의 힘(乾)"·"싹 트기 전(屯)"(CLAUDE.md 한글(한자) 규칙, 2026-11-06 리서치 §9 권고). 전통 이름(중천건·수뢰둔·뇌지예 — 첫 글자 두음)은 작은 회색 한 줄에만. 괘 글자는 한국 통용 자형(旣濟·恒)이고 화면 폰트 서브셋에 들어 있다(2026-11-07 재생성, `frontend/src/app/fonts/README.md`).
- 교차 두 문장(`cross_line`, 사주 있을 때만): 1문장 = 괘의 오행(상괘·하괘, 건·태 金 / 리 火 / 진·손 木 / 감 水 / 간·곤 土) × 내게 필요한 기운(용신) — 같음("이 괘에는 내게 꼭 필요한 쇠(金) 기운이 들어 있어요") > 生("… 키워 줘요") > 剋("… 누르니, 답은 받되 결정은 하루 묵히세요") > 설기("… 빼 가니 힘을 아끼며 움직이세요") > 보통. "용신"이라는 말은 안 쓴다(아침 한 마디와 같은 쉬운 말). 2문장 = 오늘 일진 레벨 × 변효 있음/없음 6틀. 두 체계의 길흉을 더하지 않는다.

**가드레일**(타로 리서치 §9-6 공용)
- 위기 어간(죽고 싶·자살·자해·살기 싫·목숨·사라지고 싶·뛰어내리·끝내고 싶 …)은 **괘를 뽑기 전에** 판정 → 200 `blocked:"crisis"` + 고정 문장 + 자살예방상담전화 109·정신건강위기상담 1577-0199. 질문은 저장하지 않는다. "죽도록 열심히"는 아님.
- 길이 4~80자(422). 면책 "괘는 앞날을 맞히는 도구가 아니라 지금 선택을 비춰 보는 거울이에요. 건강·법률·돈 문제는 전문가와 먼저 상의하세요." 재뽑기 없음(같은 날 같은 질문 = 같은 괘).

**하지 않는다**
- LLM 풀이·효사 384·오늘의 괘 홈 카드·저장·저널(V11-2 이후) · 하단 메뉴 칸 · 유니코드 괘 기호(䷀, 폰트에 없음) · 전통 이름을 제목으로 · 외부 해설서 문장.

## 5. 수용 기준

390px 기준.

1. 홈 까치 소식에 "까치에게 묻기" 카드(제목 + 소제목 "고민 하나를 적으면 동전 여섯 번으로 주역(周易) 괘를 뽑아 드려요", 제목 줄 오른쪽 "자세히 →")가 로그인·비로그인 모두 있고, 누르면 `/iching`이 열린다. 새소식 카드가 "까치에게 묻기가 생겼어요"다(2026-12-07까지).
2. 질문 카드에서 3자까지는 [괘 뽑기]가 비활성이고 "4자 이상 적어 주세요"가 보이며, 81자째는 입력되지 않는다. 칩을 안 고르면 "고르지 않으면 질문을 보고 정해요"가 보인다.
3. [괘 뽑기]를 누르면 질문이 따옴표로 맨 위에 보이고 동전 셋이 뒤집히며 괘 그림이 아래부터 한 줄씩 여섯 줄 쌓인 뒤(약 3초) 이름(괘 글자)·전통 이름·키워드 3·지금·앞으로 상자가 나타난다. 변효가 있으면 금색 줄에 ○ 또는 ×가 붙고 앞으로 상자에 지괘 작은 그림과 이름이 있으며, 없으면 "움직이는 줄이 없어요"로 시작한다.
4. 로그인(기본 프로필 있음)·비로그인(`/analysis` 입력값 있음)은 "오늘 일진과 함께 보면," 상자가 두 줄(문장마다 한 줄)로 있고, 둘 다 없으면 상자 대신 `/profile` 또는 `/analysis` 안내 한 줄이다.
5. 같은 질문을 같은 날 다시 물으면(공백·물음표를 바꿔도) 같은 괘·같은 변효다. 칩만 바꾸면 괘는 같고 영역 줄만 바뀐다. 기타는 영역 줄이 없다.
6. "죽고 싶어요"처럼 위기 어간이 든 질문은 괘 없이 안내 문장과 전화번호 두 개(누르면 전화)가 나온다.
7. 백엔드 테스트(`tests/application/test_iching_rules.py`·`tests/adapter/test_iching_controller.py`, 2026-11-07 통과): 팔괘 8 선 패턴 유일·오행 분포 · 64괘 문왕 차례·키·이름 유일·(위·아래) 쌍 64·전통 이름(중천건·수뢰둔·뇌지예·지천태·천지비·화수미제) · 전 문장 한글·hanja 한자만·next "앞으로" 시작 · 3동전 2,000표본 분포 · 같은 질문 같은 괘·정규화 · 300문 모드 세 경우·지괘 = 변효 뒤집기 · 영역 감지·칩 · 위기 어간 · 교차 같음/生/剋/보통 × 3레벨 · 30일 ≥ 12종 · `POST /iching/ask` 사주 없음 `cross null`·직접 입력 두 문장·`member_id` 기본 프로필 = 직접 입력·없는 회원 `date`·칩·4자 미만/81자/모르는 영역 422·위기 blocked.
8. 가로 스크롤 없음, 백엔드 호출 질문마다 1회.
